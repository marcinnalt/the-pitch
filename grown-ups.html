For parents & educators

Safe by design.
Silly on purpose.

StorySpark is built for the hand-off: you set it up once, then let them play without you hovering. Here's exactly what keeps that safe — in plain language, not policy language.

The safety pledge

The guardrails
are the product.

A story engine that can invent anything will eventually invent something you don't want at bedtime. So StorySpark doesn't get to publish a chapter until it has passed a separate safety review.

In one line

StorySpark is a storybook, not a chatbot. It has no open chat, no strangers, and nothing to scroll.

  • ✓

    Every chapter is checked

    Gemini 4 writes; a separate thinking-mode pass then reviews for kindness, age-fit and scare-factor. Chapters that fail are rewritten before anyone hears them.

  • ✓

    No strangers, no chat, no feed

    There is nobody to talk to and nowhere to wander. The only conversation is with the story, and the only options are the ones on the page.

  • ✓

    Drawings stay in the family

    Photos of drawings and voice recordings are used for the adventure in front of you, on your device. There is no kid profile and no cloud gallery.

  • ✓

    Kids never type

    Voice and pictures only — no comment box, no search bar, no keyboard to get lost in. Reading is optional everywhere.

  • ✓

    Scary gets softened

    A dragon can be grumpy, but it can't be cruel. Peril stays small and reversible, and every worry is resolved before the chapter ends.

  • ✓

    A grown-up holds the controls

    You start the session, choose the age band and decide when it's done. No autoplay into the next adventure, no upsell mid-story.

The never list

Things we
won't do.

Short list. Long commitment. These are product rules, not settings you have to find and switch off.

Never sell attention

No ads, no upsells inside a story, no “watch this next”. A finished adventure stays finished.

Never keep a kid's voice

Recordings exist for the session, then they're gone. No voiceprints, no training on your family.

Never pretend to be a friend

StorySpark is a storybook character, not a companion. It never asks a child to keep a secret or come back tomorrow.

Never use a cliffhanger

No “but then…!” designed to keep them playing. Every chapter lands softly, even the exciting ones.

Screen time

Twenty minutes.
Then the end.

The best screen time is the kind that ends before anybody melts down. StorySpark is designed around a short session with a clear finish — not a bottomless playlist.

  • ✓

    A timer you can see

    The last chapter starts with a gentle warning: “One more page, then we say goodnight.”

  • ✓

    No autoplay

    When the adventure ends, it stays ended. A grown-up starts the next one, on purpose.

  • ✓

    A landing, not a hook

    Every story closes with something to do away from the screen: retell it, draw it, or answer one question.

Questions, answered

The things
grown-ups ask.

Does my child need to be able to read?

No. Everything is spoken aloud and pictured with big, obvious choices. A four-year-old can play the whole adventure with a voice and one finger. Text is shown for the grown-ups who want to follow along.

Is this just a chatbot with a cartoon skin?

No. There's no open text box and no free conversation. StorySpark generates a structured chapter, offers a fixed set of choices, and waits. A separate safety pass reviews the chapter before it plays.

The child is talking to a storybook character — not to an assistant that can be talked into anything.

What do you keep about my kid?

No kid accounts, no profiles, no advertising identifiers. A drawing and a voice recording are used to build the adventure in progress and stay on the family device. End the session and the recordings go with it.

How scary can a story get?

Peril is small, reversible and always resolved. A grumpy dragon, a dark hallway, a lost toy — yes. Cruelty, real violence, death or anything that follows a child to bed — no. The age band changes the language and length, never the safety floor.

Can siblings or a whole class play together?

Yes. One drawing can hold two heroes, and turn-taking is built into the choices. For classrooms, the best setup is one device on the carpet and one very loud narrator.

Does it work offline?

That's the design goal: speech, narration and story state stay on the device, so the adventure keeps working when the Wi-Fi doesn't. The playable preview on this site is a static front-end demo — it shows the shape of the experience, not the full engine.

What will it cost?

This is a concept pitch, so there's no price yet. The intent is a single family licence with the twelve lesson worlds included — no ads, no subscription for the core library, and no paying to unlock the ending of a story.

Run it at home

One line.
That's the install.

The whole front end is static — no build step, no package manager, no account. Python serves it. The local model is optional; without it the studio and quest use their scripted content.

Python 3
1

Clone and serve in one line

Paste this into a terminal. It fetches the files, enters the folder and starts a local server.

git clone https://github.com/marcinnalt/the-pitch.git && cd the-pitch && python3 -m http.server 8000

Open http://localhost:8000. Profiles, avatars, the bookshelf and the quest work right away.

2

Optional: connect a local model

Install Ollama, pull an open-weight model, then run the included FastAPI adapter.

python3 -m venv .venv
source .venv/bin/activate
pip install -r server/requirements.txt
ollama pull gemma3:12b
uvicorn server.app:app --reload --port 8080

Then set window.STORYSPARK_API = "/api/chapter"; in play.html and window.STORYSPARK_QUEST_API = "/api/quest"; in game.html.

No terminal? The public demo at marcinnalt.github.io/the-pitch runs the full interface with scripted content — no install required.
